Six changes applied

Your notes, and what each one turned into.

  1. 1Row type is now unmistakable. The rail went 4px → 10px, each type gained a matching background wash, and every row carries a type label (Stop, Travel, Meal, Prep, Errand, Buffer, Free). Three channels for type. Status still lives only in words, because exports strip pictographs.
  2. 2Every minute from 07:30 to 22:00 is now accounted for — the four gaps are filled with the travel legs and buffers that were always implied but not drawn, and each half-day header states its span and says “no gaps”. Details are also much fuller: routes with line names, fares, distances, transfer counts, queue allowances, verified-hours dates, ranking weights, and why a warned row is still shown.
  3. 3Text enlarged throughout — body 15→16px, clock 11.5→13px with the duration on its own line, titles 13.5→15px, captions and details 11.5→13px, chips 9.5→11px.
  4. 4Details stay collapsed by default, as approved — except Taipei 101, which is opened to show what a warned row explains.
  5. 5Fallback stays inline after the rows it affects, as approved.
  6. 6Header is now 3/1, as asked. Worth knowing what that means: the donor's CSS has a locked 260px and no aspect-ratio anywhere — 3/1 is what its README claims. So this is a deliberate deviation from the donor's code toward its documentation, and it needs a register entry (D10) or the parity gate will read it as drift.
  7. 7Variants are real buttons now, pressed state and all.
  8. 8You have a map. It plots the four stops at true relative geometry — longitude scaled by cos(25.04°) so nothing is distorted — with the route in visit order and a scale bar. It makes the useful thing visible immediately: stops 1 and 2 are 70 m apart, Taipei 101 is 6.5 km east.
  1. 9Every stop links out to a real map app, and the whole day links as a transit route — which follows a pattern the app already uses, redirecting to TripAdvisor and Wikimedia rather than faking richer content. Toggle China trip to see the Amap variant. Two things the build must get right, both easy to get wrong: Amap takes longitude first, and it expects GCJ-02 while ours are WGS-84 from OpenStreetMap — unconverted, the pin lands 100–500 m off, which is the wrong block in Shanghai. Taiwan and Hong Kong stay on Google Maps; only mainland China switches.

Kept as decided

  • Street tiles are a reopened decision, not a build task. Decide the offline asset policy for the webapp closed with “no tile map”, on three grounds: the exports contain no map so screen and export agree by construction, tiles are the largest remote dependency in an app whose premise is a plane and a hotel with no network, and the element inventory found the map is the one element Auto-Bill's visual language cannot reach. The coordinate plot above honours all three — no network, no licence, and Pillow can draw the same figure into the PDF and poster.
  • Street tiles stay out. Confirmed — the coordinate plot does the job, so Decide the offline asset policy for the webapp is not reopened. The outbound links cover the case where you genuinely want streets: they hand off to an app that already has them, offline caches and all, instead of this app growing a tile dependency.
